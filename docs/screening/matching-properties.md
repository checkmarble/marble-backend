# Matching fields and continuous screening blacklist

Audited on **2 November 2026**, for [MAR-2421](https://linear.app/marble-eu/issue/MAR-2421/only-send-the-matchable-and-configured-fields-to-motiva-on-continuous).

A blacklist of **52 informational fields** is applied to reduce query size and stored `search_input` for continuous screening **`dataset_updated`** events. All other properties, including unknown fields, are kept. The code also excludes `topics` and `programId`.

**Versions analysed:** [Motiva v0.12.1](https://github.com/apognu/motiva/releases/tag/v0.12.1) and [Yente v5.5.1](https://github.com/opensanctions/yente/releases/tag/v5.5.1), the latest stable releases on the audit date. Yente pins **Nomenklatura 4.17.5** and **FollowTheMoney 4.11.2**. Motiva bundles FtM at **`e4ee9f2`** (v4.9.1 + 2 commits).

## Scope

- Delta: `Person`, `Company`, `Organization`, `Vessel`, `Airplane`, `LegalEntity` ([worker list](../../usecases/continuous_screening/worker_apply_delta_file.go)).
- Screening and freeform: `Thing`, `Person`, `Organization`, `Vehicle` ([DTO](../../dto/screening_refine_query_dto.go), [configuration](../../dto/screening_config_dto.go)). Their parent schemas are included in the inventory.
- The `Position` schema is out of scope. Its historical `sourceUrl` definition is not used for this audit. The separate `Person:position` property is nonmatchable in both analysed models and is included in the blacklist.

## How the lists were built

1. Examined the **released source code** of Motiva v0.12.1 and Yente v5.5.1, including the Nomenklatura version pinned by Yente and the FtM models used by each engine.
2. Collected explicit property reads, selections by **type** or **`matchable`**, preprocessing and candidate selection across all algorithms enabled in these releases. Preserved their union.
3. For each exclusion: identified no relevant property read in these paths; **verified the absence of a `matchable` icon in the official documentation**, then checked YAML overrides and type defaults.

Algorithms examined: **Motiva:** `name-based`, `name-qualified`, `logic-v1`, `marble-v0`; **Yente:** `name-based`, `name-qualified`, `logic-v1`, `logic-v2`, `regression-v1`. `best` selects `logic-v1` in Motiva and defaults to `logic-v2` in Yente. Older releases and algorithms not enabled by these releases are outside this audit.

## Fields to preserve

These fields are used **or conservatively preserved** because a generic path can select them. This does not mean every algorithm uses every field.

`weak_alias_match` reads `weakAlias`/`abbreviation`; name analysis uses name components, `title` and `nameSuffix`. `gender` and `birthPlace` have their own features. **`matchable: false` alone is insufficient to exclude a field.**

## Blacklist: 52 fields

These `properties` keys are **nonmatchable in the documentation reviewed**, for the schemas in scope.

| Informational role | Fields to remove from the query and `search_input` |
| --- | --- |
| Descriptive text | `notes`, `description`, `biography`, `summary`, `indexText` |
| Provenance and metadata | `sourceUrl`, `publisherUrl`, `alephUrl`, `wikipediaUrl`, `publisher`, `createdAt`, `modifiedAt`, `retrievedAt`, `riskSource`, `keywords`, `program` |
| Administrative classification | `classification`, `legalForm`, `sector`, `status`, `taxStatus`, `caemCode`, `fssCode`, `okopfCode`, `oksmCode`, `icijId` |
| Person description | `appearance`, `education`, `ethnicity`, `eyeColor`, `hairColor`, `height`, `weight`, `political`, `position`, `profession`, `religion`, `spokenLanguage` |
| Financial value | `amount`, `amountEur`, `amountUsd`, `currency`, `capital` |
| Vehicle or vessel description | `manufacturer`, `model`, `type`, `deadweightTonnage`, `grossRegisteredTonnage`, `tonnage`, `navigationArea`, `pastTypes`, `registrationPort` |

Documentation checked: [Thing](https://followthemoney.tech/explorer/schemata/Thing/), [Person](https://followthemoney.tech/explorer/schemata/Person/), [LegalEntity](https://followthemoney.tech/explorer/schemata/LegalEntity/), [Company](https://followthemoney.tech/explorer/schemata/Company/), [Value](https://followthemoney.tech/explorer/schemata/Value/), [Vehicle](https://followthemoney.tech/explorer/schemata/Vehicle/), [Vessel](https://followthemoney.tech/explorer/schemata/Vessel/), [Airplane](https://followthemoney.tech/explorer/schemata/Airplane/). `indexText` can serve indexing/full-text search; its removal here concerns only the entity **sent as a query**, not the indexed dataset.

These 52 fields supplement the existing exclusions: **`topics`** (not an appropriate filter when searching the client dataset) and **`programId`** (reserved for the source table in that dataset).

## Maintenance

**When changing the algorithm, engine, FtM model or supported schemas, update this document and the blacklist together.** Also revalidate custom schemas and arbitrary field options (`nm_name_property`). When in doubt, preserve the field.

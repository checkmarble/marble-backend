## Interfaces for following tasks

```go
type TracfinRepository interface {
    GetTracfinConfiguration(context.Context, Executor, string) (models.TracfinConfiguration, error)
    SaveTracfinConfiguration(context.Context, Executor, string, models.TracfinConfiguration, int64) error
    GetTracfinDraft(context.Context, Executor, string, string) (models.TracfinDraft, error)
    CreateTracfinDraft(context.Context, Executor, string, string, models.TracfinDraft) error
    SaveTracfinDraft(context.Context, Executor, string, string, models.TracfinDraft, int64) error
    SaveTracfinExport(context.Context, Executor, string, string, models.TracfinExport, int64, *string) error
}
```

String argument order: org ID, then case ID for draft/export methods. Write argument order: scope, model, expected content revision; SaveTracfinExport finally takes expected nullable previous export ID. Nil means there must be no export. No new ID is generated in persistence: configurations/drafts use existing org/case IDs, export ID is generated by the future export usecase.

All methods accept the caller's existing pool/transaction Executor. No method begins, commits, or rolls back transactions. Writes return error; callers can read back persisted revision/timestamps inside the same transaction.

`SaveTracfinConfiguration(..., expectedRevision=0)` is insert-only with revision 1 and ON CONFLICT DO NOTHING. Positive expected revision means conditional update, increment by one. Negative revisions are bad parameters. `CreateTracfinDraft` is insert-only and starts at revision 1 regardless of supplied revision. `SaveTracfinDraft` requires expected revision >=1 and increments exactly once. Zero affected rows on any write produces `models.ConflictError`, also covering disappeared/out-of-scope case writes without leaking existence. Malformed/mismatched explicit model scope is `models.BadParameterError`.

Both getters return `models.NotFoundError` when absent. In particular absent organization configuration is explicit, and draft creation never reads/requires an existing configuration row: Task4 can create a wholly manual draft with empty settings/mappings and its own diagnostic, without EditOrganization. No case-outcome/inbox/permission rules are invented in this layer; Task7 checks those before repository use.

Organization/case filtering is mandatory. Draft read joins cases on both IDs; insert selects the verified case/org within the INSERT; content/export updates have both scoped predicates and an EXISTS check against the current case/org pair. SQL foreign keys prevent absent references. No silent upsert can overwrite an existing draft. Config scope and draft outer scope are stored as columns; client content cannot change those IDs.

`last_export` is independent: draft serialization excludes it and draft saves never update it. SaveTracfinExport changes only last_export under draft-revision comparison plus `last_export->>'id' IS NOT DISTINCT FROM expected::text`, which handles SQL NULL and concurrent publication. It checks export.DraftRevision equals expectedRevision and requires a nonempty export ID. Export saves leave revision, content, UpdatedAt and UpdatedBy unchanged. Blob cleanup/publication belongs to Task6; this layer does no blob I/O.

Date/author handling: CreatedAt/UpdatedAt are assigned by PostgreSQL defaults on creation; content edits set UpdatedAt=CURRENT_TIMESTAMP. Caller-supplied model timestamps/revisions are ignored. UpdatedBy is the server-authenticated actor passed in the model, persisted as a UUID foreign key to existing users(id), not a client-controlled request field. It represents the latest content editor (creation actor until the first edit). No new CreatedBy model field was invented. Export.CreatedAt belongs to immutable export metadata supplied by the future server export flow.

No speculative `tracfin_usecase.go` was created merely to hold unimplemented usecase methods; the complete minimal repository interface is ready for Task4 to embed/consume.

## Isolation/concurrency review

PKs provide one configuration/org and one draft/case. All mutations use atomic INSERT DO NOTHING or UPDATE predicates; none performs read-then-unconditional-write. Content revisions protect both document and frozen configuration changes. Export pointer publication uses both expected content revision and prior export ID, including nil. Export publication does not invalidate content edits through a hidden revision increment. Draft saves do not reset previous successful export. Cross-org draft rows, if ever corrupted outside this repository, are not read or modified unless cases also confirms matching organization.

No blockers or known implementation concerns. Migration application and full authorization wrappers are intentionally deferred to their authorized later tasks.
